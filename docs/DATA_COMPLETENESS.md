# 数据完整性矩阵

本轮基于 GitHub `main` 的 `b83a2eb` 补齐数据完整性处理，不更换架构、研究页面或生产数据源。生产状态依据用户提供的生产验收结论和仓库现有记录；本地自动化测试使用隔离 PostgreSQL 和明确标识的源结构夹具，**不代表 Streamlit Cloud 实际联网成功**。

缺失类型：A＝源可用但 adapter/parser 问题；B＝当前源缺字段，需要可靠补充源；C＝生产接口失败/超时；D＝暂无可信来源，应保持缺失；E＝实时数据缺失，不应阻塞研究。无缺失标为“—”，多重原因可并列。

## 本轮行为与验收

- 普通搜索 BJ 只读缓存（包括过期缓存及持久化名单），不启动 BJ 请求；沪深首次无缓存时继续现有获取逻辑，已有缓存优先返回。
- 管理员原“更新基础证券名单”仅刷新 SH/SZ；新增“单独更新北交所名单（最长45秒）”。两者分别授权、写入、报告结果，状态表仍显示已有各交易所名单。失败不删除旧缓存。
- BJ 45秒是整个数据子进程的预算，涵盖导入和分页；单次HTTP连接/读取预算为5/40秒。其他数据源仍使用12秒子进程预算及3/5秒HTTP预算。TLS验证、凭据隔离、固定错误分类、失败冷却保持启用。管理员可通过 stock_info_bj_name_code 单接口诊断看到固定失败类别和耗时，不输出响应体或凭据。
- 三个指数仍分别读取/刷新 index:sina:<symbol>；返回数据保留逐条来源和stale，部分失败可保留旧指数缓存并附安全 diagnostics 分类。新增深证、创业板独立诊断项，不重新依赖 Eastmoney 实时快照。
- 财务原始指标和数值按源保留，摘要只匹配明确别名。不能解析或非有限数值不补零；不同单位、每股指标和增长率不会被模糊匹配成总额。
- `python -m pytest -q` 验证缓存回退、旧股本污染防护、BJ独立预算/刷新、财务解析、政策日期和指数部分失败。测试数量以本轮实际输出为准，不以旧任务的186项为目标。

## Streamlit Cloud 后续验证

1. 分别刷新沪深与BJ，确认沪深成功不等待BJ；BJ若仍超时，记录单接口固定类别和耗时。查看BJ返回的真实字段，不将放宽预算描述为接口已恢复。
2. 查阅旧深市缓存和重新刷新后的公司资料：公司“总股本”应缺失，不能显示A股股本。SH未提供的行业/股本继续缺失。
3. 对有官方财报的股票手动更新财务，逐项比对源值、单位和报告期；源缺字段必须继续缺失。
4. 独立诊断三个Sina历史指数，确认失败不会抹掉其他指数和旧缓存，页面不冒充实时行情。
5. 手动刷新gov.cn政策，核对真实发布日期。只有链接/标题没有明确发布日期的记录不得进入新政策缓存。
