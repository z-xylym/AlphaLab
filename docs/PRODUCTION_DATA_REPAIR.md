## 股票名单与价格彻底分离

新增三个独立公开证券名单读取：

- **security_master_sh**：使用AKShare的上交所公开列表适配器，主板A股与科创板最多两个并发请求；某一板块失败不抹去另一板块已验证的记录。
- **stock_info_sz_name_code**：深交所A股列表，可保留接口实际提供的上市日期、行业及总股本。
- **stock_info_bj_name_code**：北交所公开列表。

不使用stock_info_a_code_name聚合接口，避免一家交易所失败使整个聚合列表丢失；不使用全市场快照反推或生成证券。代码按接口返回记录规范化为6位，校验交易所代码范围，保留真实名称。**这些新增列表源尚需在Streamlit生产机器上验证**，不因“官方”就假设永远可达。

分别缓存到现有public_cache的master:v1:SH/SZ/BJ，并批量upsert现有stock_master。无需新表/迁移。每条检索记录保留exchange/source/fetched_at/stale，价格明确为None。代码搜索只读取对应交易所；名称/简称/关键词读取当前成功返回的部分名单，最多三个并发。

成功一次后后续搜索不再抓实时快照。若某交易所失败，优先保留缓存/stock_master中的已有真实历史记录，清除这些检索记录中的价格并标记stale；没有历史记录时不生成代码或名称。部分源失败时结果不保证全市场覆盖。历史快照形成的旧stock_master也仅可作为带原来源与时间的历史名称索引，不表示仍在上市。

模拟成交与回测的现有非ST检查继续保留；证券身份记录stale时拒绝启动模拟/回测，不为恢复页面放宽交易风控。持仓手工记录可以检索已知证券，但没有行情时市值/盈亏/集中度不可用，而不是按0计算。

## 页面与刷新

- **首页自动只读缓存**，无缓存快速提示。点击“更新可用公共源（新浪指数与官方政策）”才有限并行请求新源。成功后存现有公共缓存，重载不重复抓取。
- 三个指数独立缓存，只显示成功取得的真实日线；缺少的指数不补值，拒绝未来日期与无效价格。
- **个股页**移除spot()调用。没有快照时价格显示暂无可靠数据，自选、名称检索、日线、财务、主营与研究报告可独立运行。
- “更新基础证券名单”明确刷新公开名单。“更新该公司研究数据”并行刷新新浪日线、财务、主营；不调用失败的公司资料接口。首次没有该数据缓存仍可请求已验证源。
- 缓存过期时立即返回旧值并标记stale，不先等待上游失败；需要新数据时用明确刷新按钮。刷新失败保留原内容和原抓取时间，绝不把旧内容伪装为刚抓到。
- 历史缓存不会无提示地自动更新：页面必须保留来源、抓取/数据日期和stale标记。更换CA/用户/数据库不在本次范围，也不需要新增Secret。

首屏只读少量数据库缓存，不再被坏源12秒串行卡住；实际耗时仍受数据库/Cloud冷启动影响，不能凭开发测试承诺固定生产秒数。首次证券列表或手动刷新可能等待provider上限（12秒）及存储耗时，期间保留spinner与旧缓存。公共目录写入改为每500行批量upsert，避免逐证券数千次往返。

## 政府网parser具体修复

旧实现只检查li内第一个a、YYYY-MM-DD日期且标题至少8字。新解析器：

- 检查所有文档链接及其邻近单条记录容器，支持time[datetime]、data-date/data-pubtime及中文年月日、斜线/点分日期。
- 支持嵌入JSON/JSON-LD和纯JSON赋值的数据记录，识别标题、官方文档链接、发布日字段的常见大小写形式；绝不eval JavaScript。
- 没有静态记录时，最多读取3个明确引用的同源官方iframe/政策脚本/JSON目录；不追踪第三方API，不绕过登录/验证码或来源限制。
- 只允许www.gov.cn HTTPS文档链接与同源有限重定向；历史http官方链接仅升级为同一官方站点HTTPS。不从URL日期猜测发布日期，也不把页头日期附到多个不相关标题。
- 请求仍在provider总超时内；单资源限制2MB。只保存标题、已给出的发布日期与官方链接等索引元数据，措施与影响依旧需单独核对原文。

**验证边界：** 开发机器读取官方索引被其代理拒绝，因此无法声称已对当前生产原页做真实内容验收。已测试静态HTML、嵌入JSON、官方重定向及JSON目录这些格式。如果当前页面用未识别的动态接口、反爬页或其他结构，仍将报PROVIDER_SCHEMA_CHANGED，不虚构成功。合并后务必先复测government_policy_index，取得CONNECTED后手动更新首页缓存。

## 合并后的验收顺序

1. 合并PR，Community Cloud **Reboot app**，无需更改Secrets、迁移或初始化管理员；不要清空原缓存。
2. 管理员诊断 **security_master_sh / stock_info_sz_name_code / stock_info_bj_name_code**。至少相应交易所接口CONNECTED后，在个股页点“更新基础证券名单”，确认缓存成功；诊断本身只读，不会预热名单。
3. 搜索600868、梅雁、梅雁吉祥；如SH源不可用，先用已成功交易所的真实名称/代码验证。检查来源/时间/交易所、价格暂无可靠数据；重载和再搜索应不依赖spot。
4. 打开个股，检查新浪日线与最近日期、不复权标记、财务报表期及主营构成；公司资料缺项不能阻断它们。生成报告应明确缺失估值/实时价格，不能补编。
5. 添加自选、手工持仓并重登检查保存；没有快照时市值不可计算是预期。模拟与回测只在基础身份新鲜、非风险警示且其他既有条件满足时测试，不下真实订单。
6. 诊断 **stock_zh_index_daily**（默认上证）和 **government_policy_index**。回首页点击更新，查看三个指数实际返回日期、政策标题/发布日期/官方原文。个别失败保留其他成功缓存，不伪造完整覆盖。
7. 再次打开首页，确认只读缓存、显示读取耗时；不要再看到自动请求旧东方财富源引发的长等待。可手动刷新个股数据，确认失败时旧时间不被更新。
8. 行业/概念与全市场规则筛选当前允许显示暂不可用；旧缓存仍标记过时，不能拿主数据冒充价格筛选。它们不应拖慢首页/个股。

若新官方基础列表也被生产限制且历史缓存为空，搜索仍会明确不可用。需将这些具体诊断类别带回再决定合规预热或另一可靠主数据供应商，不能把本PR的结构修复当作新源可用性的生产证明。
